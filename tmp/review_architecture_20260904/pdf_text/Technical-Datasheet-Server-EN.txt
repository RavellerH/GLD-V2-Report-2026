2 Overview and architecture
2.1 Application overview
The Server provides an application-side data and command pipeline targeted for deployment on a customer VM.

    Runtime                     Node-RED                                               Ingress                         MQTT

    Integrity                   CRC + AES-GCM                                          Target                          Customer VM

●      Receives and separates uplink, status, topology, and integrity-path data.
●      Validates frames before data enters the normal application path.
●      Routes authenticated alarm events and separates manual/test input.
●      Builds authenticated high-level mode commands.


2.2 Server logical architecture
The pipeline separates transport, integrity, application routing, storage, and command downlink.

         MQTT ingress                        Frame gate                        Security gate                           Application                      Outputs


                               receive                           validate                            authorize                              route




           Broker input                     Length + CRC                     AES-GCM + replay                         Alarm + topology              Dataset / command


                                                               Figure 1. Server application logical pipeline.

    Transport                                     MQTT through the broker selected for deployment.

    Integrity                                     Frame structure, length, CRC, authentication, semantic checks, and replay policy.

    Application                                   Decoded data, alarm routing, topology, engineering UI, and commands.


2.3 MQTT input categories
Inputs are functionally separated so status, topology, payload, and integrity events are not treated as the same data.

    Category                                Purpose                                                          Downstream path

    Device uplink                           Carries frames/data from the field                               Validation and decode

    Gateway status                          Gateway communication state                                      Monitoring/status

    Topology                                Parent, discovery, and route information                         Engineering topology view

    Integrity/raw                           Validation failures or observability                             Quarantine/integrity path

    Note: Each input category is mapped to a separate processing path.

3 Frame validation and security
3.1 Frame validation
A frame must pass structural checks before authentication and semantic processing.

    Stage                                     Description

    Receive                                   Message received from MQTT

    Structure                                 Format and mandatory fields

    Length                                    Frame/payload size is checked

    CRC                                       Transport integrity is checked

    Security/semantic                         Enters the authentication gate
                                                            Figure 2. Frame-validation gate sequence.

●      Frames failing structure/length/CRC do not become decoded production data.
●      Validation errors can still be routed to an integrity/diagnostic path.


3.2 AES-128-GCM authentication
GasleakDetector payloads are authenticated and decrypted with a required runtime key.

    Stage                                     Description

    Encrypted payload                         Received after the frame gate

    Runtime key                               Required and mapped to key ID

    AES-128-GCM                               Decrypt + authentication-tag check

    Semantic validation                       Identity/role and value constraints

    Valid output                              Only then enters application routing
                                                               Figure 3. Field-payload security gate.

    Note: A runtime key is required; a payload is rejected when authentication cannot be completed.


3.3 Replay, nonce reuse, and quarantine
Authenticated but repeated data can still be rejected so old events are not reprocessed as new data.

    Condition                                    Decision                                    Path

    Authentication failure                       Reject                                      Integrity/quarantine

    Replay detected                              Reject                                      Integrity/quarantine

    Nonce reuse                                  Reject                                      Integrity/quarantine

    Semantic invalid                             Reject                                      Integrity/quarantine

    Valid and fresh                              Accept                                      Decoded/application

    Anti-replay state                        The Server deployment must configure persistent storage.

    Service recovery                         With that configuration, anti-replay state is reloaded after a service restart.

6 Data model, storage, and security
6.1 Application data model
The Server converts device data into application fields used by storage, topology display, and alarms.

 Field                             Meaning                                                               Use

 node ID                           Source-node identifier.                                               Device and topology correlation.

 gas class / gas name              Classification result and its display name.                           Detection status in the application.

 confidence                        Inference-result confidence value.                                    Context for result interpretation.

 battery mV                        Battery voltage reported by the device.                               Power monitoring.

 alarm                             Device alarm state.                                                   Alarm indication in the application interface.

 external power                    External power-source state.                                          Power-supply diagnostics.

 sequence                          Source message sequence number.                                       Ordering and repetition detection.

 gateway                           Gateway that received the data.                                       Communication-path correlation.

 last seen                         Time at which data was last received.                                 Connectivity state in the application.


6.2 Dataset record schema
The dataset recorder stores identity, acquisition context, eight sensor values, gain, sensor status, and an idempotency key in each
record.

 Group                            Fields                                                           Description

 Identity                         Device, node, and unique-record identity                         Source identity and unique record key.

 Context                          Mode, sequence, time, label, and nulling profile                 Acquisition context for each record.

 Sensor voltages                  Eight validated sensor values                                    One value for each channel.

 Gain                             Per-channel gain                                                 Acquisition gain for each channel.

 Sensor health                    Eight-channel validity state                                     Validity state for each sensor channel.

 Feature order                    Canonical sensor order                                           Preserves dataset-structure consistency.

 Note: Each record has a unique 64-character identifier so that resubmission of the same record does not create a duplicate in primary storage.


6.3 Dataset admission rules
A record is accepted only when all data-integrity requirements are satisfied before storage.

 Check                                         Requirement

 Mode                                          The record must use engineering dataset mode.

 Source identity                               The device identity must be valid, consistent with the ingress path, and match the record node identity.

 Sequence and time                             Sequence and timestamp must be within the unsigned 32-bit integer range.

 Nulling profile                               The profile identifier is within the 1-255 range.

 Label                                         Required, limited to safe characters, and no more than 31 characters.

 Sensor-value count                            Exactly eight voltage values, all finite.

 Gain                                          Each gain is one of 1, 2, 4, 8, 16, 32, or 64.

 Sensor status                                 All sensor status values indicate valid.

 Feature order                                 Must match the canonical MQ8, MQ135, MQ3, MQ5, MQ4, MQ7, MQ6, MQ2 order.

 Idempotency                                   The record key is checked before writing so that the same record is not duplicated.

6.5 Deployment security requirements
The Server is installed on customer infrastructure. The following controls apply when services are not restricted to a loopback
interface.
●      Broker connections use TLS and authentication consistent with customer policy.
●      Credentials and cryptographic material are supplied through the runtime environment or a secret store, not embedded in application
       files.
●      The deployment must configure persistent anti-replay storage so protection can be restored after a service restart.
●      Database, broker, and web-application access is restricted by customer network controls and service accounts.
●      Backup, retention, operating-system patching, and VM monitoring form part of customer infrastructure operations.

    Area                    Server application behavior                                   Deployment responsibility

    VM runtime              Runs the Node-RED services and application interface.         The customer provides the VM and selects Linux or Windows.
