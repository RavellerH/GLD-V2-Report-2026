4.2 Multi-hop and failover
An alternate parent and rediscovery maintain continuity when the active parent is no longer healthy.

    Stage                                     Description

    Healthy route                             Serving CH -> transit(s) -> Gateway

    Health failure                            Timeout/HELLO ACK/alarm ACK failure

    Rediscovery                               Builds new candidates

    Recovered route                           New parent follows discovery
                                                                         Figure 7. CH route failover.

    Note: Multi-hop and failover have been validated at the ITB IoT Lab. The replacement parent follows discovery and is not fixed to a specific
    identity.

    Active configuration                     Verified through device readback.

    Note: Nominal calculation before loss: STAR 20 dBm and MESH 25 dBm.



5 Networking and security
5.1 IP network, broker, and TLS profile
When the TLS Gateway profile is selected, the Gateway and Server each establish their own TLS session to the broker; the broker
is the termination/trust boundary.

            Gateway                   TLS session A                           MQTT broker                          TLS session B                         Server


                           encrypt                           terminate                              new session                         decrypt




            TLS client A                CA verified                           Terminates both                         CA verified                      TLS client B


                                                      Figure 8. Two TLS sessions in the TLS deployment profile.

●      The TLS Gateway profile requires a Root CA and a system epoch that meets the trusted-time threshold.
●      The Server flow supports credentials and CA-verified TLS to the broker.
●      In the TLS profile, the Gateway and Server use two separate TLS sessions, each terminating at the broker.


5.2 Layered security boundaries
Payload security and transport security protect different layers and segments.

    Layer                            Coverage                                           Function                                         Termination

    AES-128-GCM                      GasleakDetector payload                            Confidentiality + authentication                 Server decoder

    Gateway TLS                      Gateway - broker                                   MQTT transport protection                        Broker

    Server TLS                       Server - broker                                    MQTT transport protection                        Broker

    Command auth                     High-level downlink                                Authorization + payload authentication           Target application

    Note: CH and Gateway forward the encrypted field payload; it is decrypted/authenticated at the Server.
